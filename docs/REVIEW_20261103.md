# 点検メモ 2026-11-03（クロより）

## 1. これは何をする仕組み？（1枚まとめ）

**Anu の社内ポータル。「よく使うリンクを並べておく、ブックマーク帳のページ」です。**

- 中身は `index.html` 1枚だけ（点検前）。README・試験・自動化（CI）・サーバーはありません。
- 開くと、リンクのカードが並びます。「Add Link」で追加、えんぴつで編集、ごみ箱で削除。
- リンクは **見ている人のブラウザの中（localStorage）** にだけ保存されます。別のパソコンやスマホとは共有されません。
- 最初から入っているのは「disposal sheet」（Googleスプレッドシート）1件です（`index.html` 425行目）。
- **メール・LINE・X・出品サイトなどへ送る／出品するコードは、ありませんでした。** 外へ出る通信は Google Fonts（文字の形）の読み込みだけです。
- 今回の点検でコードは一度も「本番」へ向けて動かしていません（試験は自分のパソコン内の画面だけ）。

## 4. 試験の結果

- 部品の試験: `node --test tests/links-lib.test.js` → **6件中6件 成功**（Node v22）。
- 画面の確認: ブラウザ（Chromium）で自分のファイルを開いて確認しました。
  - 壊れた保存データでも画面が出る
  - `javascript:` のURLは保存されない
  - 名前に `<b id=pwn>` を入れても、画面に差し込まれない
  - Cancel ボタン上で Enter を押しても保存されない
  - 画面の試験は手作業の一回きりで、ファイルとしては残していません。
- 外部サイトへは何も送っていません（フォントの読み込みは試験中ブロックしました）。

## 5. 提案（今回はやっていません）

1. 共有したいなら、リンクを入れる場所をサーバー側（または共有スプレッドシート）にする。今は人ごとにばらばら。
2. README に「何のページか・どこで公開しているか・誰が直すか」を書く。
3. GitHub Actions で `node --test` を自動で回す。
4. 「書き出し／読み込み」ボタンを付け、リンクのバックアップをとれるようにする。
5. フォントを自分のサーバーに置く（外部に頼らない）。
